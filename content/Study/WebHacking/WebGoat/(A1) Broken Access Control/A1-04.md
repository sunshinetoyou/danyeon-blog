## 인증 쿠키 개념

인증 쿠키(Authentication cookies)는 사용자의 신원을 확인하기 위해 자주 사용되는 방식이다.<br>
Client가 Server에게 인증 요청(ex, 로그인)을 보내면, 서버 단에서 요청한 유저를 인증하고, 세션을 생성한다. 또한 생성된 세션 키를 Client에게 보내준다.<br>
이후 Client는 세션이 살아있는 동안 Server와 통신을 위해서 추가적인 인증 절차를 수행할 필요가 없다. 단지 Server에 요청을 보낼 때 쿠키에 세션키를 넣어주면 된다.  

![[Pasted image 20260305102117.png]]
*▲ 인증 쿠키 발급 과정 (출처: https://medium.com/@KumarHalder/session-based-authentication-cookie-06a5f84c4c6b)*

클라이언트(브라우저)에 저장된 인증 쿠키는 공격자가 악용하기 좋은 수단 중 하나이다.<br>
이 페이지에서는 인증 쿠키가 **예측 가능한 패턴**을 갖거나, **무결성 검증이 부재**하다면 접근 제어가 우회될 가능성을 보여준다.

## 실습 문제(인증 쿠키 스푸핑)

### 목표
알려진 계정(webgoat, admin)의 인증 쿠키를 확인하여 Tom 계정의 인증 쿠키를 추측하여 세션 탈취를 하자.

### Recon


![[Pasted image 20260305104948.png]]
*▲ 로그인 창*

| user name | password |
| --------- | -------- |
| webgoat   | webgoat  |
| admin     | admin    |

이렇게 로그인 창과 두 계정이 주어진다.<br>
![[Pasted image 20260305105238.png]]
*▲ webgoat 계정 인증 쿠키 확인*

Burp Suite로 로그인 패킷을 캡처하면, `spoof_auth`라는 인증 토큰을 획득할 수 있다.<br>
두 계정의 spoof_auth 값은 다음과 같다.

| account | spoof_auth                                       |
| ------- | ------------------------------------------------ |
| webgoat | NjQ1NjUyNzI2YzY0NDk2NjcyNjk3NDYxNmY2NzYyNjU3Nw== |
| admin   | NjQ1NjUyNzI2YzY0NDk2NjcyNjk2ZTY5NmQ2NDYx         |

`==`이 붙는 것으로 보아, Base64 인코딩 되어있을 가능성이 높아보인다. 

### Solve

획득한 인증 토큰(spoof_auth)의 규칙을 찾는 과정을 자세히 설명한다.

![[Pasted image 20260305105835.png]]*▲ Base64 디코딩 결과(CyberChef)*

디코딩한 값은 다음과 같다.

| account | spoof_auth (Base64 Decoding)       |
| ------- | ---------------------------------- |
| webgoat | 645652726c644966726974616f67626577 |
| admin   | 645652726c64496672696e696d6461     |
서로 다른 계정임에도 불구하고, `645652726c6449667269` 값이 겹치는 것을 확인할 수 있다.<br>
이후 다른 값들(`74616f67626577`, `6e696d6461`)에 대해서는 HEX 값이 아닌가 의심되어, 해당 값만 따로 ASCII 코드로 바꿔서 따져본다.

![[Pasted image 20260305110342.png]]
*▲ HEX -> ASCII code (CyberChef)*

| account | spoof_auth (Base64 Decoding)       | Specific Part(Hex->ASCII) |
| ------- | ---------------------------------- | ------------------------- |
| webgoat | 645652726c644966726974616f67626577 | taogbew                   |
| admin   | 645652726c64496672696e696d6461     | nimda                     |
account의 역순의 문자열임을 확인하였다. (webgoat -> taogbew)

이러면 목표 계정인 `Tom`의 인증 쿠키는 다음과 같이 `???`을 계산하고 Base64 인코딩 해주면 구할 수 있다.

| account | spoof_auth (Base64 Decoding) | Specific Part(Hex->ASCII) |
| ------- | ---------------------------- | ------------------------- |
| Tom     | 645652726c6449667269 + `???` | moT                       |
그러면 Tom 계정의 인증 쿠키는 `NjQ1NjUyNzI2YzY0NDk2NjcyNjk2ZDZmNTQ=` 임을 추측할 수 있다.

이제 크롬 브라우저의 `DevTools` > `Application` > `Cookies` 페이지에서 `spoof_auth` 값을 변조한다.
![[Pasted image 20260305111523.png]]
*▲ Tom의 인증 쿠키로 변조 (Chrome DevTools)*

그리고, 다시 로그인 요청을 보내면 성공이다.
